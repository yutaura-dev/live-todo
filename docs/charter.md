# Charter — live-todo

このプロジェクトのアイデンティティを定義する文書。**変更には ADR が必須**。

## 存在意義 (Why)

自分がやるべきことを記憶して、こなしていくのは面倒で、しかも自分はすぐ忘れる。live-todo は各ツールからやるべきことを自動で集め、優先度をつけて「今やるべきこと」を示し、AI が片付けられるものは先に片付けておく。

### 解決する課題

- やるべきことが Slack・メール・GitHub・カレンダー・ドキュメントなど複数のツールに散らばっていて、すべてを見に行かないと把握できない
- 覚えておくこと自体が負担で、忘れて対応が漏れる
- 元のツール側で状況が変わっても（解決済み、マージ済み、返信済みなど）気づけず、自分の todo リストと現実がずれる
- 調べもの・下書き・要約など、AI に任せられる作業にも自分の時間を使っている

## 想定ユーザー (Who)

作者 1 人。会社用・私用の両方のアカウントを持ち、日常的に複数のツールを使う。

各ツール純正の通知・保存機能（Slack の「後で」、GitHub の通知、メールのスターなど）はツールごとに閉じている。どれも横断的な優先度付けや、状況変化に合わせた自動更新はしてくれない。

## やること (In Scope)

- 次の Source から、自分の todo になるものを自動で取得する: Slack / Gmail / GitHub / Google Calendar / Google Docs / Notion / Outlook（Mail・Calendar）/ Teams
- 取得したものにラベルと優先度を付け、「今やるべきこと」を示す
- ユーザーが定義したルールで、カスタムラベルを付ける
- Task を Epic → Task の 2 段で管理する。Epic は自動で作り、Task を振り分ける
- ポーリングで Source の状況変化を検知し、Task を自動で更新する
- GitHub Projects のようなカンバン UI で Task を管理する。手動での Task 追加もできる
- Task ごとに AI Agent と会話・依頼ができ、AI が片付けられる Task は先回りして処理する（Pre-work）
- LLM プロバイダ（Claude / OpenAI / Gemini / Azure OpenAI / Bedrock など）を選べる

## やらないこと (Out of Scope) ⚠ 重要

- **承認なしでの外部への書き込み**: 返信・コメント・送信・ステータス変更など、外部サービスへの書き込みは必ずユーザーの承認（Approval）を経る。全自動実行はしない
- **共有・マルチユーザー**: 他人とのタスク共有、他人へのアサイン、チーム利用はしない
- **クラウド同期・サーバー保存**: データを自前のサーバーやクラウドに置かない。複数端末間の同期もしない
- **一般的な todo アプリとしての作り込み**: 手動追加は自動収集の補助として扱う。手動管理中心の機能（凝ったサブタスク、繰り返しタスクなど）には力を入れない

## 隣接プロジェクトとの境界

- 各 Source の代替クライアントにはならない。メッセージやメールを読み書きする本格的な UI は元のツールに任せ、live-todo からは元のツールへのリンクで遷移する
- 推論は外部の LLM API に任せ、モデルの学習・ホスティングはしない

## 成功条件 (Success Criteria)

- 毎朝 live-todo を開けば、その日にやるべきことが分かる状態になっている
- 各ツールを巡回して todo を探す習慣がなくなる

## 撤退条件 (Sunset Criteria) ⚠ 重要

- **2 週間連続で開かなかったら凍結する**。忘れる問題を解決するアプリが、このアプリ自体で同じ問題を再現しているため
- **結局毎日元のツールを直接見に行っていると気づいたら**、取得精度を見直す。それでも改善しなければ凍結する
- **トークン管理や API 変更への追従に、月に数時間以上かかる状態が続いたら**、対応する Source を絞る

## 前提と制約

- **データはローカルに置く**: Source Item、Task、Agent Thread、認証情報はすべて利用者の PC に保存する
- **推論は外部の LLM API を使う**: タスクの内容は、選択した LLM プロバイダに送信される
- **会社と私用で使える LLM が違う**: 会社のデータは会社が許可した LLM プロバイダにだけ送る。当面は「1 台の PC には会社用か私用か一方のデータだけを入れ、LLM Profile は PC 単位で 1 つ」という運用でこの制約を守る。将来はアカウントごとに LLM Profile を切り替えられるようにする
- 各 Source の API 利用規約とレート制限に従う
