# ADR-0020: アプリが用意したルールは、ユーザーが有効にしたときだけ書き込む

- **Status**: Accepted
- **Date**: 2026-11-28
- **Deciders**: YutaUra

## Context

ADR-0014 は、ユーザーが決めたルールを、そのルールの範囲の書き込みの承認とみなした。あわせて「アプリが自分で決めたルール（組み込みのルール）で書き込むことはしない」と決め、charter にもそう書いた。

一方で、「Task を完了にしたら、そのスレッドの受け取り済みのメールをアーカイブする」のように、多くの人が同じ形で使う片付けがある。ユーザーが毎回同じルールを書くのは手間がかかる。今の実装も、完了にした Task のメールのアーカイブを、ルールとは別の決め打ちで行っている。

## Decision

- アプリが中身を用意したルール（組み込みのルール）を持つ。ユーザーが作るルールと同じ Rule として扱う（specs/rule.spec.ts）
- 組み込みのルールは、初めは止めておく。ユーザーが有効にしたことを、そのルールを決めたことと同じにみなし、そのルールの範囲の書き込みの承認にする
- ユーザーは組み込みのルールを、有効にする・止めるだけできる。書き換えも消すこともできない
- アプリを更新して組み込みのルールの中身が変わったら、止めた状態に戻す。ユーザーが有効にしたのは前の中身なので、新しい中身で有効にし直してもらう
- charter の「アプリが自分で決めたルールで書き込むことはしない」を、「アプリが用意したルールは、ユーザーが有効にしたときだけ書き込む」に改める

## Alternatives Considered

- **組み込みのルールを初めから有効にし、止められるようにする**: ユーザーが一度も確かめずに書き込みが起き、charter の「承認なしの外部書き込みはしない」の例外を広げすぎる
- **組み込みのルールを持たず、ユーザーに毎回書いてもらう**: charter の文面のままでよいが、多くの人が同じ形で使う片付けのたびに手が要る
- **完了にした Task のメールのアーカイブを、ルールの外の決め打ちのまま残す**: 承認の経路が 2 つになり、止め方もばらばらになる

## Consequences

### Positive

- よく使う片付けを、ルールを書かずに有効にするだけで使える
- 書き込みの承認の経路が、ユーザーが確かめる・ルールを決めた（有効にした）の 2 つにそろう

### Negative

- アプリの更新で組み込みのルールが止まると、ユーザーは有効にし直す手間がかかる
