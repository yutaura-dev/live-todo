# ADR-0011: 定期の Task は決まりから作り、作る入口を 1 つにする

- **Status**: Accepted
- **Date**: 2026-11-26
- **Deciders**: YutaUra

## Context

毎月の月初めに請求書を送るような、決まった時期に決まった手順でやる仕事がある。どの Source からも通知は来ないので、
これまでは live-todo に出てこなかった。また将来、Task の中から「これは定期の Task にしませんか」と AI が提案したい場面がある。

## Decision

- 定期の Task の決まり（`recurring_tasks`）を持つ。タイトル・メモ・次にやることのひな形・いつ作るか（いまは毎月 N 日、何日前から出すか）
- 時期が来たら、決まりから Task を作る（1 時間おきに確かめる）。タイトルに何月分かを付け、メモを状況（brief）に載せる
  - 日付は PC のタイムゾーンで数える。その月にない日（31 日など）は月末
  - 同じ月の分は二度作らない。作った Task を消しても作り直さない（決まりに最後に作った月を持つ）
  - 前の月の分が終わっていなくても今月の分は作り、そのことを状況に書く（作らずにおくと、今月の分を忘れるおそれがあるため）
  - 登録した時点で時期を過ぎた今月の分は、明示したときだけ作る
- 作る日の 7 日前から、まだ作っていない月の分を Todo のレーンに予告（ゴースト）として出す。本当の Task ではないので、ドラッグも削除もできない。「今すぐ作る」で、その月の分を作る日を待たずに作れる
- 決まりを作る入口は、手で登録する・Task から作る（`createRecurringFromTask`）の 2 つ。Task から作るときは、タイトルと次にやること（済んだ印などを外したもの）をひな形にする
- AI が「定期の Task にしませんか」と提案するときも、`createRecurringFromTask` に渡す下書き（いつ作るか・メモ）を作るだけにする。決まりを作るのはユーザーが承認してから

## Alternatives Considered

- **前の月の分が終わっていなければ作らない**: 今月の分を忘れるおそれがある。終わっていないことは状況に書けば分かる
- **毎回 Task をコピーする（決まりを持たない）**: 時期や手順を変えたいときに、直す場所がない

## Consequences

### Positive

- 通知の来ない、決まった仕事も live-todo に出てくる
- 前の月の分を残したまま次の月が来ても、気づける

### Negative

- いまは毎月だけ。毎週や「月の最初の営業日」は、必要になったら `schedule` の種類を足す
