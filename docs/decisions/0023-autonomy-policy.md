# ADR-0023: 自動でやってよい範囲はユーザーが決め、決めたことを承認とみなす

- **Status**: Accepted
- **Date**: 2026-11-28
- **Deciders**: YutaUra

## Context

AI が片付けられるものは先回りして進めたい（charter）。一方で charter は、外への書き込みは必ずユーザーの承認を経るとしている。

先回りの範囲は人によって違う。issue へのコメントは自動でしてよいが、PR は draft までにしたい、ローカルでも worktree の外は触らせたくない、などである。これを Generation が計画を立てるたびに決めると、どこまで自動で動くかがユーザーから見えない。

## Decision

- 自動でやってよい範囲（Autonomy Policy）を PC に 1 つ持ち、ユーザーが決める（specs/autonomy-policy.spec.ts）
- 操作を 4 つの段に分ける。どの操作がどの段かは provider が決める
  1. 調べる（書き込みを伴わない調査）
  2. ローカルの書き込み（worktree 内のファイル変更。ADR-0012 の sandbox が書ける場所を閉じ込める）
  3. 外への書き込み（下書き）
  4. 外への書き込み（本番）
- Agent の作業は 1 回の中で多くの操作をするので、渡す道具で段を決める（読むだけ = 調べる、直す = ローカルの書き込み）
- ユーザーは操作ごとに上限を決める（issue へのコメントは本番まで、PR は下書きまで など）。全体の上限は持たない。決めていない操作は、ローカルの書き込みまでを自動でやる（新しく足された操作が、知らないうちに外に書き込まないように）
- 自動で書き込む先は、その Task が追っている事実そのもの（PR #42 へのコメント など）に限る。同じアカウントでも、ほかの対象への書き込みはユーザーが承認する（読んだ内容に仕込まれた指示で、データを書き出さないように）。作る操作（issue #12 を直す draft の PR を作る など）は、作る場所が元の事実と同じ場所（同じリポジトリ・同じスレッド）のときだけ、作る元の事実への書き込みとして扱う。作ったものはその Task の事実に加える（作ったものから作っても、同じ場所の外には広がらない）
- 書き込みで果たされる Action Item も、番が来たら自動でやるかボタンで頼むかを持ち、Generation が計画の中で決める。ボタンで頼むものは、範囲に入っていても自動では書き込まない。この指定は範囲を狭める向きにしか効かず（「自動」にしても範囲の外は自動にならない）、範囲を広げられるのはユーザーだけなので、「Generation が自動でやるかを毎回決める」案とは違う
- 自動の承認には、そのときの操作と上限を残す（あとで範囲を変えても、なぜ書き込んだかを追えるように）
- 自動で書き込むのは、計画を立てたときの版が今も同じときだけ。自動で頼むのは Action Item ごとに 1 回だけで、失敗したあとはユーザーが頼む
- 範囲に入るものは、計画の Action Item の番が来たら自動で始め、外への書き込みも確かめずに書き込む。ユーザーが範囲を決めたことを、その範囲の書き込みの承認とみなす（ADR-0014 のルールと同じ考え方の例外として charter に足す）。下書きも外への書き込みとして扱うが、ユーザーが下書きまで自動でよいとしていれば、自動で書き込む
- 範囲に入らないものは、今までどおりユーザーが頼む・承認する
- Rule がなくても成り立つようにする。Rule を捉え直すときに、この範囲の設定も見直しの対象になりうる

## Alternatives Considered

- **Generation が計画を立てるときに、自動でやるかを毎回決める**: どこまで自動で動くかがユーザーから見えず、承認なしの書き込みを AI が決めることになる
- **全体の上限を持つ**: 設定は少なくなるが、あとで provider に足された操作まで、ユーザーが見ないまま上限まで自動で書き込む
- **外への書き込みは、下書きも含めて自動にしない**: charter のままでよいが、issue へのコメントのような決まった書き込みのたびに手が要る

## Consequences

### Positive

- 先回りの範囲を、ユーザーが自分で決められる
- 自動で動くことが、設定から読める

### Negative

- 範囲を広げすぎると、思わぬ書き込みが起きうる（全体の上限を持たず、操作ごとにだけ上限を決めるようにして抑える）
- 自動の書き込みの中身は、Generation が他人の書いた内容を読んで作る。読んだ内容に仕込まれた指示（prompt injection）で、意図しない書き込みが起きうる。書き込む先を Task が追っている事実そのものに限り、計画を立てたときの中身と版のままだけ書き込み、Action Item ごとに 1 回だけにして抑える
- 書き込む先が Task の事実かは、AI（Decisions）が振り分けた事実も含めて見る。仕込まれた指示を含む他人の issue やメールを AI がこの Task に振り分けると、そこへ自動で書き込みうる。本当にそこへ書き込みたいこともあるので、確かに付いた事実だけに絞ることはせず、振り分けのハーネスの作り込みと精度の改善で抑える
- 自動で始める Agent（読むだけ）にも Web のページ取得を渡す。読んだ内容に仕込まれた指示で、ページを開くだけで本文を外に出しうるが、調べる作業に要るので渡し、ハーネスで抑える
