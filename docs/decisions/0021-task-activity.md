# ADR-0021: Task の変化は Task Activity として持ち、既読は最後に見た時刻で決める

- **Status**: Accepted
- **Date**: 2026-11-28
- **Deciders**: YutaUra

## Context

ADR-0003・ADR-0007 は、Task の項目の変化を Task Change として 1 件ずつ持ち、未読の Task Change がある Task に更新マークを付けると決めた。spec にすると、次の無理が出た。

- 「何が起きたか」（出来事の記録）と「ユーザーが見たか」（注目の状態）を 1 つに持っていて、既読にする道（開いた・自分で直した・まとめる・最近片付いたもの）が増えるたびに決まりが込み入った
- 項目の変化でない出来事（AI が作業をやめた理由・外への書き込みができなかったこと）を表せず、今の状況（brief）の書き換えに寄せるしかなかった
- 新しく出た Task の仕分けまで更新マークになり、「知っている Task が変わった」と「まだ見ていない Task」が区別できなかった

## Decision

- Task Change の集約をやめ、Task の中に、Task に起きた出来事（Task Activity）の履歴を持つ。起きた順に足すだけで、書き換えない（Source Item の Activity と同じ考え方）
- 出来事の種類は、できた・項目が変わった・AI が作業をやめた・書き込めなかった。だれが起こしたかを持つ
- 既読は出来事ごとに持たず、Task が「ユーザーが最後に見た時刻」を持つ
  - 更新マーク: 最後に見たあとの変化を項目ごとにまとめ、最後に変えたのがユーザー以外の項目がある、または項目を持たない出来事（作業をやめた・書き込めなかった）がある
  - 新着: まだ一度も見ていない。新しく出た Task の仕分けは更新マークにしない
  - 最近片付いたもの: 終わった Task のうち、更新マークがあるもの
  - どれも保存せず、履歴と最後に見た時刻から導いて見せる
- 履歴はユーザーに見せる記録で、ほかの集約はこれを読んで反応しない（集約どうしの反応は spec の links で書く）
- 「Source の出来事」（Source Item の Activity）と「Task の出来事」（Task Activity）と言い分ける

## Alternatives Considered

- **Task Change を集約のまま残す**: 既読を 1 件ずつ持つので、既読にする道ごとに操作が増え、項目の変化でない出来事も表せない
- **既読を、ユーザーの注目を持つ別の集約（読み取りモデル）に分ける**: 筋はよいが、作者 1 人のローカルアプリでは、Task と同じところに置いても取り合いにならない。導いて見せるだけにする

## Consequences

### Positive

- 既読の決まりが「最後に見た時刻」1 つになり、項目の変化でない出来事も更新マークにできる
- Source Item と Task で、出来事の持ち方がそろう

### Negative

- Task の中で履歴が増え続ける。どこまで持つかは実装のときに決める
