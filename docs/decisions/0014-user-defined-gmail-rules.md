# ADR-0014: 利用者が決めた Gmail のルールは、決めたことを承認とみなして自動で当てる

- **Status**: Accepted
- **Date**: 2026-11-26
- **Deciders**: YutaUra

## Context

請求書のメールが届いたら「レシート」のラベルを付けて既読にする、のような決まった片付けを、毎回承認して行うのは手間がかかる。
一方で charter は、外部への書き込みは必ずユーザーの承認を経て、全自動では行わないと決めている。

ルールの中身（どのメールに何をするか）は人によって違うので、アプリに組み込むべきではない。

## Decision

- Gmail のアカウントごとに、利用者が設定画面でルールを決められるようにする（`gmailAccounts[].rules`）
  - 条件: 用件（請求・支払いなど）、種類（メルマガ・お知らせ・人からのメール）、差出人のアドレス（メーリングリストなら List-Id）に含む文字、件名に含む文字。すべて満たしたときに当てる。差出人の表示名は送る側が自由に付けられるので、条件に使わない
  - 操作: ラベルを付ける（なければ作る）、既読にする、アーカイブする。ゴミ箱に入れる・送るなど、ほかの操作はルールに書けない（設定の検証で断る）
- 利用者がルールを決めたことを、そのルールの範囲の書き込みの承認とみなし、条件に合うメールに自動で当てる。charter の「承認なしでの外部への書き込み」に、この例外を書き足す
- 当てるのは、ルールを作ったあとに届いたメールだけ。過去のメールにまとめて書き込まない
- 同じメールに同じルールは一度しか当てず、当てるたびに何をしたかを `gmail_rule_runs` に残す。失敗してもやり直さない（書き込みを二重に効かせないため）
- アプリが自分で決めたルール（組み込みのルール）で書き込むことはしない

## Alternatives Considered

- **毎回、案内を出して承認してもらう（日程が過ぎた招待と同じ）**: charter のままでよいが、決まった片付けのたびに手が要り、ルールにする意味が薄い
- **アプリに「請求書はレシートに」のようなルールを組み込む**: 人によってラベルや片付け方が違うので合わない

## Consequences

### Positive

- 決まった片付けを、毎回承認せずに済む
- 何をしたかが残るので、ルールが思わぬメールに当たっても後から追える

### Negative

- 条件の決め方を誤ると、意図しないメールにラベルや既読が付く（操作をラベルの付け外しに限り、ゴミ箱や送信はできないようにしている。Gmail で元に戻せる）
- 用件は Decisions の判定なので、外れることがある
